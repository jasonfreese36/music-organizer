# Music Organizer 1.4 使用手册

[项目中文说明](../README.zh-CN.md) · [English](../README.md) · [许可与第三方组件](../THIRD_PARTY_NOTICES.md)

适用 Windows 10/11 x64。双击 **MusicOrganizer.exe** 即可，无需安装 Python 或另外配置音频工具。首次启动会解压内置组件，请等待数秒。

1.4 的苹果设备预设、原盘独立归档和语言选择，见[中文说明中的“开始使用”](../README.zh-CN.md#开始使用)。默认仍为常规曲库，以下默认备份规则针对常规曲库；苹果设备模式按其独立归档选项处理，源文件始终保留。语言可在高级设置的外观页面选择，保存并重启后生效。

1. 选择音乐来源和一个独立目标目录，例如 `E:\NewMusic` → `E:\NewMusic_Organized`。
2. 点击“只读扫描”，预览音频格式与原标签。选中音轨可更正标签，或为整张专辑指定本地封面/图片网址。
3. 点击“开始整理”。进度、运行日志和结果均在窗口内。关闭或点击停止会结束当前任务，已完成项目保留；重跑同一目标库可继续和补全。
4. 完成后查看 `Needs Review\Review.csv` 和 `Library Records\Latest Run.json`。匹配不充分的音轨仍在 Albums 中，失败项目在报告中列出。

## 平台加密音频（1.3 新增）

整理时先复制并校验加密原件，再通过内置本地工具恢复音频，继续进入既有的 FLAC / MP3 / AAC 转换、去重、命名、标签和内嵌封面流程。源文件保留；解密本身不联网、不上传音频，在线资料检索仍由“数据源”控制。

| 平台 | 已实现的格式 / 方案 | 密钥要求与限制 |
|---|---|---|
| 网易云音乐 | NCM、UC 缓存 | NCM 使用内置 ncmdump；UC 适用于受支持的旧缓存 |
| QQ 音乐 | QMC 静态 / Map / RC4，MFLAC / MGG 内嵌 EKey、QTag，TM | STag、musicex 等版本需要对应本地 EKey / 原始密钥 |
| 酷狗音乐 | 旧 KGM / KGMA / VPR、crypto v3、KGG / crypto v5 | v5 需要对应 EKey，可导入本地 KGMusicV3.db 或 kgg.keys |
| 酷我音乐 | 旧 KWM / KWMA | 新加密变体可能不兼容 |
| 咪咕音乐 | MG3D | 部分旧 WAV 可自动恢复；其他受支持文件需对应 fileKey / 掩码；**MGM 尚未支持** |

此表描述已实现的方案，不保证各平台全部历史及最新版本都能处理。公开 QMC 测试向量、16 种生成的容器样本和一份真实 NCM 副本已验证；其他平台的真实下载文件仍可能出现新变体。同一扩展名可能对应不同版本。扫描只核对容器和密钥匹配，最终以实际解密及完整音频校验为准。

### 高级设置 → 平台音频

提供自动处理开关、解密并行数（默认 2）、完整解码校验（默认开启）、支持范围和待处理文件列表。初始外观、命名、转换继续保持 v1.1 默认，条件规则列表仍为空。

1. 只读扫描后查看“需要密钥”“版本未支持”等状态。
2. “导入密钥文件”支持已有 JSON / TAB 文本、酷狗 kgg.keys 和 KGMusicV3.db；也可“添加单曲密钥”，选择音频并粘贴对应值，无需编写规则或代码。
3. 导入后自动重查匹配，再开始整理。咪咕 fileKey 区分大小写；QQ 与酷狗 EKey 不能互用。

酷狗数据库仅从用户明确选择的文件读取。程序在临时目录解密副本并检查完整性，再以只读 SQLite 连接提取歌曲密钥，原数据库不改动。不自动遍历客户端目录、不读取账号密码，不提供平台音乐下载或获取密钥的服务。

单曲记录保存在本机 `%LOCALAPPDATA%\MusicOrganizer\Platform Keys.json`，按普通本地配置文件保存，未另加密码。外部密钥文件只保存路径引用。密钥值不进入进程命令行、日志、报告或导出配置；导出配置也不携带密钥文件路径。不同密钥同时匹配时提示冲突，需为单曲指定准确记录。

批量 JSON 示例（key 填已有对应值）；也支持每行“文件名 TAB QQ EKey”或酷狗“KeyId$EKey”：

```json
{"schema":1,"entries":[{"file":"Song.mflac","key":"YOUR_EKEY","key_type":"qmc_ekey"}]}
```

类型包括 qmc_ekey、qmc_raw、kgg_ekey、kgg_raw、migu_file_key、migu_mask。原始 QQ / 酷狗密钥为 Base64，咪咕直接掩码为 32 位大写十六进制 ASCII。完整路径优先匹配，其次文件名或容器内密钥标识。无需编写 JSON 也可用单曲窗口添加。

NCM 原件沿用 `Disc Archives/NCM Originals`；其他平台进入 `Disc Archives/Platform Originals/QQ Music` 等英文目录。结果记录于 `Library Records/Platform Audio.csv` 和 `Latest Run.json`，失败项进入待处理报告。关闭自动解密时只归档平台原件。

解密核心随 EXE 打包，以 1 MiB 块流式处理，不把整首音频载入内存。实际并行数受总音频任务数限制，机械硬盘建议 1–2。完整校验需要额外解码，耗时受大小和编码影响。取消会终止子进程，临时文件不会发布到 Albums。解密后的真实音频格式参与原有条件规则，不按原加密扩展名判断音质。

## 高级设置（1.2 新增，按需启用）

首次打开保持 v1.1 的浅色紫色外观、目录结构和转换策略。新规则列表为空，不会自动套用任何示例。升级会保留已有偏好。新增选项均在侧栏“高级设置”，无需设置即可继续原来的扫描与整理流程。

### 外观

提供浅色、深色、跟随系统三种模式，以及鸢尾紫、海湾蓝、松石绿、蔷薇粉、琥珀橙五种主题色。即时生效并记住选择，不重新扫描曲库。

### 目录与命名

用下拉预设选择艺术家、年份、风格等文件夹结构，或选择轨号在前、歌名在前、艺术家在前、仅歌名等文件名习惯。可点选“插入字段”进一步组合；模板固定文字可自行调整，`/` 表示文件夹层级。文件扩展名由实际输出格式添加。

| 用途 | 默认模板 | 其他例子 |
|---|---|---|
| 专辑文件夹 | `Albums/{albumartist}/{year_prefix}{album}{edition}` | `Library/{genre}/{albumartist}/{album}{edition}` |
| 音轨文件名 | `{track:02d} - {title}` | `{title} - {artist} - {track:02d}` |
| 多碟目录 | `Disc {disc:02d}` | `CD {disc:02d}` |

目录可使用 `{albumartist}`、`{artist}`、`{album}`、`{year}`、`{year_prefix}`、`{date}`、`{genre}`、`{label}`、`{edition}`；文件名还可使用 `{title}`、`{track}`、`{disc}`、`{codec}`、`{samplerate}`、`{bits}`。数字可用 `:02d`、`:03d`、`:04d` 补零。`year_prefix` 在有年份时包含年份和分隔符，无年份时为空。专辑目录必须包含 `{album}`。版本标识即使未放进模板也会保留，避免合并 LP、多声道等不同版本。

多碟可选单独的碟目录、碟号放在文件名前或平铺。非法路径字符自动清理；不允许盘符、向上跳转或报告/原盘的保留目录。未知资料使用 Unknown 类别。面板实时显示样例或当前选中音轨的路径。

### 音频转换

- 默认无损和 DSD 播放版为 FLAC，现有 MP3/AAC 保留编码音频，其他有损转 AAC；可按需改为 MP3/AAC 便携库。
- PCM 采样率可保留、只降低高于上限的音频、或统一到指定值；FLAC 位深可保留或选 16/24/32 bit。可保留声道、混缩立体声或单声道。
- SWResample 侧重速度，SoXR 使用 28-bit 精度重采样。降低整数位深可选三角抖动、高通三角抖动或关闭。
- FLAC 压缩级别 0–12，默认已有 FLAC 直接保留；勾选重新压缩后才对已有 FLAC 应用压缩级别。压缩级别不会改变音质。
- MP3 支持 VBR V0–V9、CBR 64–320 kbps；AAC 支持 96–512 kbps（立体声目标码率，多声道按比例增加）。可选择 MP3 ID3v2.3 / v2.4 或保留版本。
- 目标编码与现有 MP3/AAC 相同时，默认保留编码，码率、采样率和声道选项不会触发重新编码。需要应用这些参数时启用“目标编码相同时，也重新编码”或规则中的同编码重新编码选项。更换有损编码会再次有损，源文件始终保留；转 FLAC 不会恢复有损来源的音质。
- MP3 最多立体声、48 kHz；AAC 最高 96 kHz。超出编码器能力时自动适配，预览中显示。DSD/SACD 默认 88.2 kHz / 24 bit，仍保留原盘；可改为 176.4 kHz，再应用指定的 PCM 策略。
- 校验开启时，采样不变的无损转换核对 PCM 一致；重采样、混缩、量化或有损编码核对输出参数、时长和完整解码。写标签和封面始终核对编码音频未改变。

### 条件规则：全部点选，无需写代码

点击“新增规则”，或选择一个示例开始；填写名称，选条件、比较方式和阈值，再选择处理动作，点击“保存规则”。例如：

1. 来源格式 → 等于 → AAC。
2. 添加条件：音频码率 (kbps) → 大于 → 256。
3. 条件关系 → 全部满足（且）。
4. 输出格式 → MP3；可另选 MP3 CBR / VBR、码率或品质。

条件包括来源格式、音频平均码率、采样率、无损位深、声道数、源文件大小、是否无损。阈值直接填数字，单位由界面提供。码率按音频流读取，不按文件总大小推断；未知码率不会命中码率条件。有损编码的位深不参与位深条件。DSD 的码率与采样率条件使用原 DSD 参数。

支持“全部满足 / 任一满足”、启用 / 停用、复制、上移 / 下移、移除，最多 100 条规则，每条 1–8 个条件。**从上到下只采用第一条命中的启用规则；后续规则不叠加。** 未命中或动作选择“沿用默认”的字段使用“音频转换”中的设置。规则只覆盖该音轨的转换参数，命名沿用“目录与命名”。

### 整理前预览与配置复用

扫描后可在“目录与命名”“条件规则”或“配置与工具”打开只读预览，查看每个源文件命中的规则、处理结果、目标路径和同名提示，支持导出完整 CSV。预览使用当前标签和手动更正；在线补全，以及 NCM、SACD、CUE 解密或展开后的最终资料可能不同。预览不读取全部音频样本，也不解密或转换文件。

在“配置与工具”导出/导入 JSON 配置，包含外观、命名、转换、规则与来源偏好；不包含源/目标路径、音频或按专辑保存的手选资料。也可选择是否另存 cover 图片、生成 M3U8、备份附页。封面仍内嵌，DSD/CUE/NCM 原件备份仍保留。

重跑同一受管理的目标库时，凭音频校验与来源记录识别已有文件。更改命名会迁移已识别的音轨，更改编码参数会从源音频重新生成、校验后更新；先完成新的文件，再处理原输出，不反复累积同一来源的播放副本。不同录音/母带仍分别保留。

## 数据源与发行结果选择（1.1 新增）

侧栏“数据源”可分别启用标签与封面来源，并指定自动匹配的优先顺序：

| 来源 | 标签 | 封面 |
|---|---|---|
| MusicBrainz | 发行、曲目、厂牌、目录号等 | 由 Cover Art Archive 提供 |
| Cover Art Archive | — | 对应具体发行版本的封面 |
| Apple iTunes | 数字发行与曲目资料 | 专辑封面 |

关闭 MusicBrainz 的标签选项后，如仍启用 Cover Art Archive，程序会通过 MusicBrainz 定位封面所属的发行版本，只将其用于封面检索。

“测试全部来源”和各来源的“测试连接”会绕过缓存，实际访问资料接口；封面来源还会验证图片下载。结果显示可用、部分可用或失败，以及测试用时和时间。设置中“检索地区”也用于 iTunes 的地区测试。

在曲库里选中音轨，点击“查找封面与标签”：

1. 确认或修改艺术家、专辑名称，选择全部启用来源或某一个来源，再点击“搜索资料”。
2. 浏览同一专辑的不同发行版本，比较年份、地区、媒介、厂牌、目录号、封面和曲目对应关系。“曲目对照”显示哪些歌曲可以对应，未对应的曲名与轨序会保留。
3. 对一个版本点击“选用此标签”，再对另一个版本点击“选用此封面”。例如标签选 MusicBrainz、封面选 Apple iTunes，也可从同一来源的不同版本分别选用。
4. 点击“应用到预览”，然后开始整理。选择会按专辑保存，下次扫描同一源目录会恢复；已下载的手选封面和资料可以离线应用。可用“清除手选”恢复自动匹配。

“整理时自动联网”只控制整理阶段的自动查询；手动点击搜索和连接测试仍会访问在线来源。关闭某来源会停止自动查询该来源；此前明确手选并缓存的资料保留，直到清除手选。封面也可继续使用本地图片或图片链接。

选择与更正只先保存到预览配置。音频写入目标库时才应用，运行记录分别保留标签和封面的来源。

## 处理能力

- 播放格式统一为 FLAC、MP3、AAC（AAC 使用 `.m4a` 容器，能规范嵌入标签与封面）。现有 MP3/AAC 保留编码音频，ALAC、APE、WAV、AIFF、WavPack、TTA 等 PCM 无损转换为 FLAC。其他有损格式需转 AAC，会有再次有损；原文件保留在源目录。
- CUE 整轨一次解码后按采样分轨，首轨前音频保留，整轨和原 CUE 同时备份。多文件 CUE 与多碟专辑均可处理。异常 CUE 不会删除原轨。
- 浮点或超过 32 位的 PCM 原件另备份到 `Disc Archives/PCM Originals`；转换为整数 PCM 可能量化，报告会注明。
- 内置 ncmdump 1.5.1 解密 NCM，保留 NCM 原件，将解密音频并入 Albums。
- 内置 SACD Extract 0.9.0 处理 SACD ISO，输出带原盘元数据的 24-bit FLAC，提供双声道/多声道和 88.2/176.4 kHz 选择。DSF/DFF 同样保留 DSD 原件并转换。普通数据 ISO 无法作为 SACD 解码，会保留并报告。
- 本地原标签、内嵌封面及 cover/folder/front 图片优先。联网时按专辑从 MusicBrainz、Cover Art Archive、Apple iTunes 查询；核对艺术家、发行名、曲名、轨序和时长。清除平台标识字段，保留发行年份、目录号等有效信息，记录查询来源。
- 匹配时兼容中文简繁写法与全半角标点，显示和写入仍以所选发行信息的原文为准。
- 封面写入每首音轨，同时保留 cover 图片。未找到可信封面时列入待处理报告；可通过预览手动指定，无需改变源文件。
- 同一发行下按编码音频/无损 PCM 校验确认重复，避免同名误合并。内容不同的同名专辑保留 Alternate 版本；明确 LP rip/vinyl/黑胶来源单独保留 Vinyl Rip。单曲与恢复的音频按发行信息进入 Albums。
- 源目录与目标必须独立；源文件不写入、不移动、不删除。目标音轨通过临时文件完成转换、标签和音频校验后发布；已有音轨的标签更正也先暂存验证。
- 缓存在线查询、按专辑请求，默认 4 个音频任务并行。扫描预览上限 6,000 行（可筛选），实际整理处理全部扫描文件。

## 速度与空间

SSD 建议 4–8 个并行任务，机械硬盘建议 2。无损 PCM 校验默认开启；可在设置中关闭以节省解码时间。封面/标签服务有请求速率限制，缓存后重跑会更快。

目标空间应能容纳播放库、DSD/CUE/NCM 原件备份，以及最大一张整轨的临时 PCM。临时内容位于 `Library Records\Temporary`；正常结束或停止后本次临时目录会清理。意外断电留下的 `run-*` 临时目录不参与播放库，关闭程序后可手动清理。

设置、查询缓存和预览更正保存在 `%LOCALAPPDATA%\MusicOrganizer`。点击“设置与说明”可打开缓存目录与依赖许可。此工具不上传音频。

## 自动匹配的范围

服务中没有对应发行、曲名/时长不吻合、原标签过少、特殊 LP 来源或读取错误，都会在报告里保留说明。自动匹配不能保证每张专辑都能获取到权威信息；手动选择封面与更正标签后，重新整理到同一目标库即可更新已有歌曲。

## 源码与构建

应用源码及许可证位于 `MusicOrganizer-Source.zip`，依赖版本和校验值见 `resources/Dependencies.json`。在 Windows x64 上使用 Python 3.14 创建虚拟环境，安装 `requirements.txt`，运行 `python build.py --output dist`。prepare.py 下载并验证固定版本的 FFmpeg、ncmdump、SACD Extract 和 Go SDK，并收集许可；平台解密核心通过随源码附带的 Go 代码及 vendored TEA 依赖构建。Go SDK 仅构建时使用，运行 EXE 不需要安装。构建期间需要联网，测试脚本使用生成样本，不改动真实曲库。

诊断命令也支持 `--settings Profile.json` 导入同一配置，以及 `--preview --source 路径 --dest 路径 --report Preview.json` 只读导出规划。可与 `--offline`、`--organize`、`--check-tools` 组合。

EXE 未做数字签名。自有源码采用 MIT；完整版的 GPL 等依赖仍须遵守各自协议和适用的源码分发义务，详见源码包和程序内“依赖许可证”。
